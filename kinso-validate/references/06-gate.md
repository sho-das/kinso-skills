## Guards

- A total score never decides the verdict.
- Never put the user's private details into a test.

## Checks after

- **Go** = problem, buyer and way of charging hold (5+ checked signals at ladder 4 to 6 from different people; no free tool already does the job). A smaller first version or a pre-sale test is part of a go.
- **Change** = buyer, problem, region or way of charging must change. Cutting features is not a change.
- **Drop** only when the evidence shows it will not work: a free tool already does the job for this buyer, checked signals show nobody has the pain, or an earlier attempt died for a reason that still applies.
- **Dead attempts are a deciding factor.** Read the graveyard table (`RIVALS-QUICK.md` section 3, `SIGNALS.md` section 4). For each death, say whether its reason still applies today, and what is different now if it does not. "Why unknown" is a gap, not a pass.
- **Missing evidence is not a drop**: it is change (or go) plus a cheap test.
- A free tool that already does the job wins over thin evidence; a tool that takes hours and often fails is a workaround.
- Narrowest version tried before any drop.
- Counts only from rows with quote_checked = yes; data older than 18 months marked "old".
- Next test: pass signal is payment or pre-commitment, never "I would use it".
- **Fresh reviewer** writes `review/GATE-REVIEW.md`. A Critical issue stops the gate until fixed or the user says proceed.
- Checks never rewrite the skill's voice.
